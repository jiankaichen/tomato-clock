# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A native Android clock app plus a home screen widget for the owner's Pixel 9. It exists because the stock Clock app cannot save named timer presets and has no Pomodoro timer. Those two features are the priority. A stopwatch exists too; alarms and world clock are not implemented.

Kotlin, Jetpack Compose (Material 3), minSdk 31, targetSdk 35, single `app` module, no tests yet.

## Look and feel

The owner found Material You dynamic color too pale and asked for the GitHub contribution-graph look: always dark, `#0d1117` background, time shown as a grid of green cells with dim empty cells. Keep that.

- `ui/PixelGlyphs.kt` holds the `GitHub` palette and `PixelDigits`, a Canvas grid renderer used for the time on the Clock tab, the countdown dial, and the stopwatch. It supports only digits, `:`, `.` and space.
- `ui/theme/Theme.kt` is a fixed dark scheme built from that palette; there is no light theme and no dynamic color.
- No emoji anywhere. Presets carry a short uppercase `tag` (JSON key is still `emoji` for compatibility; `AppStore` migrates old emoji values) rendered by `MatrixTag`, and Pomodoro phases use `phaseTag()`.
- The launcher icon is Matrix rain of pixel digits behind a clock face, generated by `tools/gen_icon.py --install face` into `ic_launcher_foreground.xml` (the `digits` variant is the alternative). Do not hand-edit that drawable.
- The widget shows the same grid as a drawn image: `renderPixelBitmap` in `PixelGlyphs.kt` paints it into an `ImageView`. A custom-font approach (`TextClock` with a generated pixel TTF) was tried first and the Pixel launcher ignored the font, so do not go back to fonts in widget layouts. Because an image cannot update itself, the idle clock is refreshed by a once-a-minute non-wakeup exact alarm armed only while a widget exists and nothing is running, and `CountdownService` redraws the widget once a second while any timer or stopwatch is live (the service therefore also runs while a stopwatch runs).

## Environment

Nothing is installed system-wide on this WSL2 box (no sudo). Export these before any Gradle or adb command:

```bash
export JAVA_HOME=~/.jdks/jdk-17.0.20.1+1
export ANDROID_HOME=~/android-sdk
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"
```

`local.properties` already points `sdk.dir` at `~/android-sdk`.

## Commands

```bash
./gradlew assembleDebug                 # APK at app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug                  # needs a device visible to adb
./gradlew lint                          # Android lint
./gradlew :app:compileDebugKotlin       # fastest compile-only check
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb logcat -s ClockApp AndroidRuntime   # crash logs
```

adb from WSL2 usually cannot see a USB phone directly. Either run adb on the Windows side and connect over TCP (`adb tcpip 5555` there, then `adb connect <phone-ip>` here), or copy the APK to the phone and sideload it.

## Architecture

**Many sessions at once.** `data/Models.kt` `Session` is one countdown; `AppStore.sessions` is the list. Any number of plain timers (`SessionKind.TIMER`) may run concurrently, plus at most one Pomodoro phase (`WORK`, `SHORT_BREAK`, `LONG_BREAK`); starting Pomodoro replaces only the existing Pomodoro session. Timing is wall-clock based (`endAtWallMs`) so it survives process death and reboot; `remainingMs` is only valid while paused. `startedAtWallMs` orders items newest-first for the widget. Every session has a short uppercase `tag` shown by `MatrixTag`.

**`timer/CountdownController` is the only writer of session state.** All its mutators take a session id. Every transition goes through its private `apply()`, which does four things in order: persist to `AppStore`, reschedule or cancel one exact alarm per session (`AlarmManager.setAlarmClock`, request code = id hash, session id in the intent extra), start or stop `CountdownService`, and refresh the widget. Route any new transition through `apply()` so all four stay in sync.

**Finishing is idempotent and has two triggers.** The exact alarm (`CountdownAlarmReceiver`, per session) calls `onFinished(id)`; a backup tick in `CountdownService` waits for the earliest running end and calls `finishDue()`. Finished sessions stay in the list with `finished = true` until dismissed; `dismiss(id)` removes a timer but advances Pomodoro to the next phase (auto-started, or parked as paused when `autoStartNext` is off).

**Select, then Start.** Tapping a preset never starts it. It becomes a `Ready` card at the top of the Timers tab with a Start button; the preset editor's "Use once" does the same for an unsaved duration. Stopwatches likewise start only from their play button. Keep that flow.

**`timer/CountdownService`** is a foreground service (`specialUse` type) that only renders: one grouped notification per session under a summary that is the foreground notification (id 1), the backup tick, and `Ringer` while any session is finished. Notification action PendingIntents carry the session id and an `ACTION_*` string; the service forwards them to the controller.

**Stopwatches** are a separate list (`AppStore.stopwatches`, `timer/StopwatchController`, id-based), wall-clock based, no per-stopwatch notification, but a running stopwatch keeps `CountdownService` alive so it can tick the widget. There is always at least one; the tab's FAB adds more. Running or paused ones appear in the widget alongside timers.

**`data/AppStore`** is SharedPreferences + kotlinx.serialization JSON, exposed as `StateFlow`s. It is deliberately synchronous because the widget provider and broadcast receivers read it without a coroutine scope. Do not swap it for DataStore without giving those callers a sync path. It also stores each widget instance's page index (`widgetPage`), reset by every start so widgets jump to the newest item.

**`widget/ClockWidgetProvider`** is a 4x1 Matrix-style RemoteViews widget (near-black, `#39ff14`), not Glance, on purpose. Digits are bitmaps of the cell grid sized to the widget box from `getAppWidgetOptions`. Idle shows only the time, as large as the box allows. When anything is running it shows exactly one item, the most recently started timer or stopwatch, with `<` and `>` tap zones to page through the others, because Android widgets cannot take horizontal swipes. No preset chips or controls; tapping the body opens the app.

**UI** is four tabs in `ui/AppUi.kt` (Timers, Pomodoro, Stopwatch, Clock) with plain tab state, no navigation library. Timers and Stopwatch tabs are lists of cards, one per running item, with inline controls. `FinishedOverlay` sits above the scaffold for the first finished session; the alarm notification's full-screen intent opens `MainActivity` to show it on the lock screen. `ui/Common.kt` holds `formatMs`, `rememberRemaining` (200 ms polling while running) and the `CountdownDial` ring used by the Pomodoro screen.
